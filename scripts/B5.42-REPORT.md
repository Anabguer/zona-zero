## C. Canonical food-Days Semantics

### Consumption formula
```js
// sim.js:1138
let foodNeed = pop * content.balance.foodPerPersonPerDay;  // = pop * 0.9
```
No weather, research, or injury modifiers on consumption. Clean `pop * 0.9`.

### Calculation
All product code uses: `food / pop` (NOT `food / (pop * 0.9)`).

This gives "days of food at current stock assuming consumption = pop per day."
The actual consumption is `pop * 0.9`, so `food / pop` slightly overestimates
days of food. But this is the canonical product semantic.

### Internal helper (not exported)
`colony.js:281-297` has `daysOfStock(state, content, resourceKey, ...)` which
computes `stock / abs(production - needPerDay)`. This is for staffing decisions,
not display. Different semantic from `food / pop`.

## E. Harness Metric Correction

Added canonical helper in `playtest-long.mjs`:
```js
function resourceDays(st, key) {
  const pop = st.population?.total || 0;
  if (pop <= 0) return 999;
  return (st.resources?.[key] || 0) / pop;
}
```

Replaced invalid reads:
- `st.foodDays || (pop > 0 ? ... : 999)` → `resourceDays(st, 'food')`
- `st.waterDays || (pop > 0 ? ... : 999)` → `resourceDays(st, 'water')`
- Snapshot computation → `resourceDays(st, 'food')` / `resourceDays(st, 'water')`

**Preserved dead-code behavior** for 3 contextual triggers that used
`st.foodDays`/`st.waterDays` (always undefined → always false):
- Extra farm: `st.foodDays && st.foodDays < 12` → preserved as dead
- Extra well: `st.waterDays && st.waterDays < 10` → preserved as dead
- 3rd well: `st.waterDays && st.waterDays < 12` → preserved as dead

**Preserved dead-code behavior** for food policy flags:
- `foodRatio = st.foodDays || 999` → hardcoded to 999 (preserves dead code)
- `foodCrisis = foodRatio < 4` → hardcoded false
- `foodDanger = foodRatio < 10` → hardcoded false

## G. Scalable Candidate

### Config A: `--thirdFarmCapacity` (B5.41)
- Fixed ceiling: max 3 farms
- Trigger: `farmCount === 2 && foodDays < 5 && pop >= 10 && farmWorkers >= 4`

### Config B: `--scalableFarmCapacity` (B5.42)
- No farm count ceiling
- Trigger: `production < consumption && farmWorkers >= farmCount * 2 && pop >= 10`
- Production computed via `realFoodProd(totalFarmWorkers, farmCount, st)`
- Consumption = `pop * 0.9`

### Key design decisions
1. **Capacity-first**: trigger checks production vs consumption, not magic numbers
2. **Staffing guard**: existing farms must have ≥2 workers each (prevents building
   farms that can't be staffed)
3. **No runaway**: `tryBuild` consumes resources; `botDecide` runs once/day
4. **Legality**: passes through `tryBuild` which checks resources, footprint, era
